# RaceDay Bot Briefing

Этот файл нужен как быстрый контекст для следующего диалога с моделью, чтобы она сразу понимала текущее состояние проекта.

## Что это за проект

`RaceDay Bot` — Telegram-бот для отслеживания гоночных сессий.

Основная задача:
- дать пользователю персонализированный календарь гонок;
- присылать push-уведомления по подпискам;
- показывать трансляции с фильтром по языкам;
- отправлять еженедельный дайджест;
- дать администратору базовую операционную панель прямо в Telegram.

Источник данных:
- `raceday.watch`
- интеграция реализована через reverse-engineered gRPC-Web клиент в `utils/api.py`

Текущий стек:
- `Python`
- `aiogram`
- `APScheduler`
- `SQLite`
- `aiohttp`
- `python-dotenv`

## Текущая архитектура

Основные файлы:
- `main.py` — точка входа, инициализация бота, middleware, scheduler, startup/shutdown.
- `scheduler.py` — фоновые джобы: прогрев кэша, уведомления, дайджест, cleanup.
- `database.py` — слой БД на `aiosqlite`.
- `config.py` — чтение `.env`, константы и настройки.
- `utils/api.py` — клиент к API.
- `utils/formatters.py` — карточки сессий, тексты уведомлений, дайджесты.
- `handlers/` — пользовательские и админские обработчики.
- `middlewares/` — внедрение `db`, `mem`, `metrics`, throttling, подписка на канал.

Кэш:
- L1: in-memory cache (`MemoryCache`)
- L2: SQLite table `api_cache`

Хранение:
- `users`
- `subscriptions`
- `sent_notifications`
- `favorites`
- `api_cache`
- `event_log`

## Как работает scheduler

Сейчас настроено так:
- каждый час `:00` — cache warm-up
- каждый час `:05` — notifications job
- каждые 5 минут — weekly digest job, но реальная отправка идет только если:
  - у пользователя включен digest;
  - у пользователя локально понедельник;
  - локальное время пользователя совпало с `digest_time`
- раз в неделю — cleanup old `sent_notifications`

## Важные исправления, уже внесенные в код

Ниже список не просто фич, а именно исправленных багов/недочетов.

1. Исправлен вызов `notification_text(...)`
- раньше падало с ошибкой:
  - `TypeError: notification_text() missing 1 required positional argument: 'live_timings'`
- теперь `live_timings=[]` передается корректно

2. Исправлена логика mark-as-sent для уведомлений
- раньше уведомление могло попасть в `sent_notifications` до фактической успешной отправки
- теперь запись делается только после успешного `send_message`

3. Подключены `quiet hours` к реальной отправке push-уведомлений
- раньше настройка была в профиле, но не применялась в scheduler
- теперь применяется

4. Подключен `show_no_broadcast` к push-уведомлениям
- раньше настройка влияла на `/today` и `/week`, но не на scheduler notifications
- теперь влияет и на push

5. `digest_time` теперь реально работает
- раньше время дайджеста сохранялось, но weekly digest был привязан к фиксированному cron
- теперь digest проверяется по локальному времени пользователя

6. `last_seen_at` теперь обновляется и на callback-кнопках
- раньше обновлялся только на обычных сообщениях
- теперь учитываются и нажатия в inline-меню

7. Исправлены HTML-проблемы на пользовательском вводе
- экранирование добавлено для:
  - ручного ввода таймзоны
  - строки поиска

8. Активирована метрика `new_users`
- раньше счетчик существовал, но фактически не увеличивался

## Как это выглядит для пользователя

Это menu-driven бот, а не “командный терминал”.

Пользователь обычно:
1. нажимает `/start`
2. выбирает таймзону
3. получает автоподписки
4. открывает меню
5. смотрит гонки на сегодня/неделю
6. управляет подписками
7. настраивает уведомления и языки
8. получает push-уведомления и weekly digest

Карточка сессии показывает:
- название;
- статус;
- серии;
- время в локальной таймзоне пользователя;
- длительность;
- локацию;
- ссылки на трансляции;
- live timing, если используется;
- заметки, если есть.

## Как это выглядит для администратора

Админ не пользуется отдельной веб-панелью.

Он делает это прямо в Telegram:
- `/admin`
- кнопки внутри админ-меню
- `/admin_broadcast ...`

То есть текущая админка — встроенная операционная консоль для небольшого production-бота.

## Что еще может сбивать с толку

1. В коде есть callback `session:{sid}` в уведомлениях.
- При дальнейшей работе проверить, есть ли полноценный обработчик детальной карточки по этой кнопке.
- Если обработчика нет, это один из логичных следующих шагов.

2. В проекте есть сущности `favorites` и callback factories для избранного/напоминаний.
- При следующем проходе проверить, насколько этот UX полностью доведен до конца.

3. В проекте нет полноценного покрытия тестами.
- Это один из главных технических долгов.
